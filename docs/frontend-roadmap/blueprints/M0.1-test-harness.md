## 3. Why fetch needs a trampoline (read before writing the helper)

`openapi-fetch` captures `globalThis.fetch` and `globalThis.Request` **when
`createClient` runs**, i.e. when `api/gateway.ts` is first imported. A test that calls
`vi.stubGlobal('fetch', …)` afterwards is ignored by the clients. Also, the clients use
the relative base `/bff`, and Node's `Request` rejects relative URLs.

So `setup.ts` installs, before any test imports `gateway.ts`:

- a `Request` subclass that resolves relative URLs against `http://localhost`;
- a stable `fetch` function that forwards to a swappable handler.

## 4. `src/test/setup.ts`

```ts
import '@testing-library/jest-dom/vitest';
import { afterEach } from 'vitest';
import { cleanup } from '@testing-library/react';
import { resetFetchHandler, dispatchFetch } from './mockApi';

const NativeRequest = globalThis.Request;
class RelativeRequest extends NativeRequest {
  constructor(input: RequestInfo | URL, init?: RequestInit) {
    const url = typeof input === 'string' && input.startsWith('/') ? new URL(input, 'http://localhost').href : input;
    super(url, init);
  }
}
globalThis.Request = RelativeRequest as typeof Request;
globalThis.fetch = ((input: RequestInfo | URL, init?: RequestInit) => dispatchFetch(input, init)) as typeof fetch;

afterEach(() => {
  cleanup();
  resetFetchHandler();
  localStorage.clear();
  sessionStorage.clear();
});
```

## 5. `src/test/mockApi.ts`

Exports:

```ts
export interface RecordedCall { method: string; path: string; query: URLSearchParams; body: unknown }
export type RouteReply = unknown | { status: number; body?: unknown };
export function mockApi(routes: Record<string, RouteReply | ((call: RecordedCall) => RouteReply)>): { calls: RecordedCall[] };
export function dispatchFetch(input: RequestInfo | URL, init?: RequestInit): Promise<Response>;
export function resetFetchHandler(): void;
```

Behaviour:

- Route keys are `"METHOD /api/..."` (the `/bff` prefix is stripped before matching). A
  `{param}` segment matches any value: `"DELETE /api/posts/{id}"`.
- A plain value is returned as `200` JSON. `{ status, body }` returns that status (body
  as JSON when present, empty otherwise; `201` and `204` are common).
- An unmatched request fails the test loudly: return `500` with body
  `{ title: 'unmocked <METHOD> <path>' }` **and** push it to the calls so a test can see it.
- The request body is parsed as JSON when the content type is JSON, else left as text.
- `calls` is the list of every request in order, for contract assertions.

## 8. `scripts/check-rules.mjs`

Plain Node (no deps). Walks `src/` (skip `src/test/`, `*.test.ts(x)`, `index.css`,
`components/ui/theme.ts`). Rules, each with an id:

| id | Fails on |
|---|---|
| `no-hex` | `/#[0-9a-fA-F]{3,8}\b/` in a string or class (ignore `&#` entities and `#` in URLs after `?`/`/`) |
| `no-violet` | `/\b(violet|fuchsia)-\d{2,3}\b/` |
| `no-raw-bff-fetch` | `fetch(` or `XMLHttpRequest` in a file other than `api/gateway.ts` and `api/auth.ts` (the token/register calls are not in the SDK) |
| `no-fake-actor` | `addNotification(` whose 2nd argument is a string literal other than `'Marketplace'` |
| `no-console-log` | `console.log(` |

`const ENABLED_RULES = ['no-raw-bff-fetch', 'no-fake-actor', 'no-console-log'];` (M0.2 adds
the colour rules). Print `rule file:line: text` per violation and exit 1 if any.
The current code passes these three (checked on 2026-10-24: `GroupsTab.tsx:48` passes
`group.name`, a variable, which is allowed). If one fails anyway, fix the code, not the rule.
